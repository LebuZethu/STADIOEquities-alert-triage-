# Preprocessing

This document describes the data preprocessing stage for the STADIOEquities
fraud detection and AML alert triage project.

## Related file

- **Notebook:** `notebooks/01_preprocessing.ipynb`

## How to run

1. Install the project dependencies from the repository root:
2. Download the dataset (see the main README for the source) and place
   `creditcard.csv` in the `data/` folder.
3. Open `notebooks/01_preprocessing.ipynb` in VS Code or Jupyter and run the
   cells in order from top to bottom.
4. The notebook writes its output to `data/processed/` (four CSV files). These
   files are intentionally excluded from version control via `.gitignore`
   because of their size; they are regenerated by running the notebook.

## What the preprocessing does

The notebook performs the following steps, in order.

### 1. Load the data
The dataset (`creditcard.csv`) is loaded into a pandas DataFrame. It contains
284,807 transactions and 31 columns (Time, Amount, V1 to V28, and the target
column Class).

### 2. Check data quality
The notebook confirms there are no missing values in the dataset, and inspects
the column data types. This dataset is clean, so no missing-value imputation is
required.

### 3. Examine the class imbalance
The target column, Class, is heavily imbalanced. Only 492 of the 284,807
transactions are fraudulent, which is 0.172 percent of the data. A bar chart is
produced to make this imbalance visible. This imbalance is the central
challenge of the project and drives several of the decisions below.

### 4. Scale Time and Amount
The V1 to V28 features are already on a small, comparable scale because they are
the output of a PCA transformation. The Time and Amount columns, however, are on
much larger scales. They are standardised using scikit-learn's StandardScaler so
that no single feature dominates a scale-sensitive model such as logistic
regression purely because of its larger numeric range.

### 5. Split into training and test sets
The data is split into an 80 percent training set and a 20 percent test set
using a fixed random seed (random_state=42) for reproducibility. The split is
stratified on the target, which keeps the same 0.172 percent fraud ratio in both
sets. This gives a training set of 227,845 transactions and a test set of 56,962
transactions.

### 6. Balance the training set with SMOTE
SMOTE (Synthetic Minority Over-sampling Technique) is applied to the training set
only. SMOTE generates synthetic fraud examples until the two classes are equal,
which gives the models enough fraud examples to learn from.

SMOTE is applied on purpose only to the training set, never to the test set.
The test set is left with its real 0.172 percent fraud rate so that model
evaluation reflects real-world performance. Applying SMOTE to the test set would
be a form of data leakage and would produce a falsely optimistic result.

### 7. Save the processed data
The balanced training set and the untouched test set are saved to
`data/processed/` as four CSV files (training features, training labels, test
features, test labels). The feature engineering and modelling notebooks load
these files rather than repeating the preprocessing.

## Note on scaling order

In this notebook, scaling is applied before the train/test split. A stricter
approach fits the scaler on the training set only and then applies it to the
test set, to avoid any information from the test set influencing the scaling.
For this dataset the difference is negligible, because only two of the thirty
features are scaled and the dataset is large, but the stricter approach would be
preferred in a production settings.
